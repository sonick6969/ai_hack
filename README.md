# КофеСервис Регион — подготовка выезда

Локальный пилот рабочего места диспетчера: Excel или ручное сообщение → проверяемый разбор → конкретная машина → уточнения → склад и резерв → объяснение готовности → карточка инженера и печать.

Репозиторий проекта: [sonick6969/ai_hack](https://github.com/sonick6969/ai_hack). Основная ветка — `main`; также подготовлены `feat/dispatch-pilot` и `release/pilot`. Приложение запускается локально; внешнего развёртывания нет. Материалы кейса сохранены без изменений. Данные кейса вымышленные, что указано в самом Excel. Дополнительные демо-примеры помечаются отдельно и не загружаются автоматически.

## Требования

Доработка логики и редизайн от 13.11.2026 описаны в [отчёте](docs/REDESIGN_REPORT.md): регрессии до/после, разделение правил и продуктовых проверок, миграция, скриншоты и границы проверки LLM.

Проверяемая среда: Python 3.12, Node.js 22, npm 10, Linux. Нужны Python с модулем `venv` и npm. Для браузерных тестов — установленный Google Chrome (Playwright использует `channel: 'chrome'`). Приложение работает без API-ключа, внешних аккаунтов, Docker, PostgreSQL и LLM.

## Быстрый запуск

Все команды, кроме явно указанного перехода в `frontend`, выполняются из корня репозитория:

```bash
cd /home/vladimir/ai_hack
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix frontend ci
cp .env.example .env
.venv/bin/python -m backend.app.cli migrate
```

Запустить оба сервера одной командой:

```bash
bash scripts/dev.sh
```

Открыть **http://127.0.0.1:5173**. Backend: **http://127.0.0.1:8000**, OpenAPI: **http://127.0.0.1:8000/docs**. Остановить — `Ctrl+C`. Скрипт завершает только свои серверы. Если порты заняты, остановите ранее запущенные экземпляры.

Либо в двух терминалах:

```bash
# Терминал 1, корень репозитория
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir backend/app
```

```bash
# Терминал 2
cd /home/vladimir/ai_hack/frontend
npm run dev
```

Первая загрузка показывает пустую очередь. В разделе **«Импорт данных»** нажмите **«Импортировать файл кейса»** либо загрузите `Данные_к_кейсу_06 (1).xlsx`. Должны появиться **23 сообщения, 12 машин, 10 деталей, 10 правил**. Одно предупреждение об отсутствующей истории EQ12 ожидаемо. Точный повтор файла не изменяет данные и резервы. Альтернатива без интерфейса:

```bash
.venv/bin/python -m backend.app.cli import-case
# Для другого файла с той же структурой:
.venv/bin/python -m backend.app.cli import-excel /абсолютный/путь/данные.xlsx
```

Папка `data/` с SQLite создаётся автоматически и исключена из Git. Приложение не сбрасывает базу при перезапуске. Для отдельного эксперимента задайте новый путь, сохраняя основную базу:

```bash
DATABASE_PATH=./data/experiment.sqlite3 .venv/bin/python -m backend.app.cli import-case
DATABASE_PATH=./data/experiment.sqlite3 .venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

## Основной сценарий

1. В очереди найдите клиента/серийный номер или нажмите **«Новое обращение»**. Исходный текст сохраняется неизменным.
2. Откройте заявку, проверьте результат разбора и **подтвердите машину и адрес**. При противоречии запишите, как оно разрешено. Машины вне реестра направляются менеджеру; система лишь фиксирует маршрут, не отправляет сообщение.
3. Во вкладке **«02 Уточнения»** исправьте описание симптома и запишите ответы. Подставленные цитаты требуют сохранения и подтверждения. Для неизвестного ответа есть действие **«Ответ пока неизвестен»**: текст и происхождение сохраняются, обязательный вопрос остаётся открытым. Содержательный ответ со словами «не знаю причину» допускается.
4. В **«03 Детали»** запишите и согласуйте цель и состав работ. Диагностика, ремонт и обслуживание могут выполняться без замены деталей: Excel не требует план деталей для каждой такой работы. Если деталей нет, проверки совместимости, резерва и перевоза отмечаются **«Не требуется»** и не увеличивают счётчик выполненных проверок.
5. Добавьте совместимые детали, выберите склад и **подтвердите резерв**. Свободный остаток учитывает исходные резервы Excel и активные резервы пилота. Для другого города согласуйте перевоз с датой получения и укажите дату визита не раньше получения.
6. Разберите возможные дубли: объедините сообщения о той же машине/проблеме либо объясните отдельную заявку. Независимая новая проблема или другая машина сохраняются отдельно. Явное исправление прежнего симптома можно добавить к той же заявке; отменённый симптом сохраняется в истории и не включается в текущие симптомы.
7. При гарантии запишите фактически полученное согласование старшего инженера. В пилоте нет проверки его полномочий; это явно отображено в форме.
8. Когда применимые проверки справа выполнены, нажмите **«Подготовить карточку»**. Итоговый статус — **«Карточка готова к передаче»**. Откройте **«04 Карточка» → «Печать / PDF»**. Назначение инженера, время выезда и физическое получение деталей согласуются отдельно. Черновик печатается с заметной отметкой.

Любое содержательное изменение снимает подготовку и согласование. Новое сообщение также сбрасывает ответы и подтверждения. Смена машины требует новых ответов и подтверждения симптома, удаляет план деталей и освобождает собственные резервы. История ответов сохраняется. Исходные резервы из Excel не снимаются. Несохранённые формы хранятся в `sessionStorage` этой вкладки, включая переходы между этапами; при уходе из заявки появляется предупреждение.

```bash
# Изолированные временные базы, без изменения data/pilot.sqlite3
.venv/bin/python -m pytest -q

# Проверка TypeScript и production-сборка
npm --prefix frontend run build

# Отдельный корпус отрицаний, исправлений и разговорных формулировок: до/после
.venv/bin/python scripts/evaluate_language.py

# Сопоставление baseline и выбранного локального режима на одних 38 текстах
.venv/bin/python scripts/evaluate.py

# 13 заведомо заблокированных случаев и 8 разделов полной карточки
.venv/bin/python scripts/measure_pilot.py

# Сквозной Chrome-тест на отдельной свежей базе, порт 8011
bash scripts/test_browser.sh
```

Браузерный скрипт сам собирает frontend, запускает backend, проверяет `/api/health`, выполняет сценарии и останавливает свой сервер. Основную базу не изменяет. Результаты: `artifacts/browser-results.json`, скриншоты, `engineer-card.pdf`, `workflow-measurement.json`; серверный лог и SQLite находятся в новой `artifacts/browser-*/`. Для тестов уже запущенного dev-сервера используйте `npm --prefix frontend run test:e2e`: этот режим добавляет обращения в его базу и предназначен только для тестовой среды.

Фактически выполненные проверки и найденные исправления: [docs/VERIFICATION.md](docs/VERIFICATION.md). Все предсказания, числители, знаменатели, задержки, ошибки и ограничения оценки: [evaluation/REPORT.md](evaluation/REPORT.md), [evaluation/results.json](evaluation/results.json). Разметка со ссылками на исходные ячейки: [evaluation/reference.json](evaluation/reference.json); бланк независимой экспертной проверки: [evaluation/review.csv](evaluation/review.csv). Не перегенерируйте разметку ради улучшения результата; `build_reference.py` нужен только для явного пересмотра исходного набора.

## Необязательная LLM

По умолчанию `LLM_ENABLED=false`: выбранный рабочий режим — расширенный локальный разбор. Он сравнивается с простым baseline. Для подключения внешнего извлекателя в локальной `.env` задайте `LLM_ENABLED=true`, `OPENAI_API_KEY`, `LLM_MODEL`. Модель должна поддерживать Responses API и Structured Outputs. Имя модели намеренно не выбирается без данных о доступе вашей учётной записи. Тайм-аут — 3 секунды, максимум 15; автоматических повторов нет. Прокси окружения используются только при `LLM_TRUST_ENV=true`.

В LLM отправляется текст обращения только после явного включения. Адаптер использует `store:false` и строгую JSON Schema: факты, текущие/отрицаемые/прошлые/предполагаемые симптомы, цитаты, номер машины для фрагмента и неопределённости. Валидный результат меняет классификацию симптомов. Проверяются происхождение цитат, область машины и явные отрицания в полном исходнике. Ошибка, тайм-аут, отказ, некорректный JSON или неподтверждённый фрагмент ведут к локальному откату с видимым статусом. LLM не выбирает запись реестра, не ставит диагноз, не резервирует детали и не назначает готовность. Excel импортируется локально без LLM.

Живая интеграция без ключа не заявляется проверенной. Проверка адаптера выполнена с HTTP-заглушками. Формат адаптера сверялся с [официальной документацией Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

## Архитектура

Один FastAPI backend, SQLite с WAL и SQL-миграциями, React/TypeScript/Vite frontend. Зависимости зафиксированы в `requirements.txt` и `frontend/package-lock.json`.

| Модуль | Ответственность |
|---|---|
| `backend/app/importer.py` | Валидация Excel, происхождение ячеек, отчёт, атомарный импорт |
| `db.py`, `repository.py` | Хранение сообщений и заявок, версии, журнал, объединение |
| `extraction.py`, `observations.py` | Локальный разбор по областям текста и машинам, история утверждений, необязательный структурированный LLM |
| `answers.py` | Состояния ответа и совместимость с сохранёнными строковыми ответами |
| `matching.py` | Кандидаты реестра, неоднозначность, неизвестные и противоречивые данные |
| `rules.py` | Обязательные уточнения, гарантия, таблица кодов |
| `inventory.py` | Совместимость, свободный остаток, атомарные резервы, перевоз |
| `readiness.py` | Вычисление готовности и объяснение каждого препятствия |
| `card.py` | Карточка JSON и самостоятельная HTML-страница печати |
| `main.py`, `schemas.py` | API, валидация, обработка ошибок |
| `frontend/src/` | Русскоязычная очередь, формы, склад, импорт, печать и журнал |

`BEGIN IMMEDIATE` сериализует запись, предотвращая двойной резерв последней детали. Повтор подтверждения/отмены резерва идемпотентен. `revision` защищает от перезаписи из устаревшего окна; «готово» соответствует только текущей версии. Новые миграции добавляются отдельными SQL-файлами; применённые не редактируются. Резерв — выделение под выезд, не списание и не отгрузка в ERP.

Собранный frontend также обслуживается самим backend: выполните `npm --prefix frontend run build`, перезапустите backend и откройте **http://127.0.0.1:8000**. Это проверяется изолированным браузерным сценарием. Внешнего развёртывания нет.
