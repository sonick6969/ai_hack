## Что именно проверено автоматически

- Точная машина по номеру, единственный кандидат по клиенту, неоднозначность нескольких машин, опечатка клиента, кириллическая «С» в модели, адресное уточнение с отрицанием исправной машины, неизвестная модель и номер, противоречие номера/модели/клиента, несколько номеров в тексте.
- Возможные дубли только предлагаются; уточнение объединяется с сохранением сообщений. Новая проблема на той же машине, другая машина и другой клиент не объединяются. При смене версии запрос из старого окна получает 409.
- Новое обращение, которого нет в демо-наборе, введено через реальную форму: C100, s/n 119, медленная выдача кофе. Машина и адрес подтверждены, ответы сохранены, деталь F010 из Тулы добавлена и действительно зарезервирована.
- Несовместимая G100 для C200 отвергается. G200 в Москве имеет 2 физические единицы и 2 исходных резерва: новая заявка не может зарезервировать её.
- **Конкуренция за последнюю G300**: два HTTP-запроса стартуют через барьер в двух потоках; ровно один получает 200, другой 409. Итог: собственный резерв 1, свободно 0. Нельзя получить два резерва одной последней детали.
- Повтор подтверждения и отмены резерва идемпотентен. Многопозиционный резерв откатывается целиком при дефиците одной позиции. Смена машины и удаление детали освобождают только собственные резервы.
- Межскладской перевоз нельзя согласовать в день обращения. При получении на следующий рабочий день готовность всё ещё требует подходящей даты визита. Суббота и воскресенье учитываются.
- Гарантийный повтор течи у «Маяка» и новая установка «Пирса» требуют старшего инженера. У «Листа» симптом на прошлом визите не повторился, ремонт не выдумывается. У «Сквера» код узла неизвестен и сохраняется в неопределённостях.
- Для C300 код E11 не получает расшифровку от C100/C200. Код ошибки никогда не назначает деталь. «Не знаю», `E7` и произвольное слово не закрывают вопрос о точном коде.
- Подготовка неполной заявки отвергается. Содержательная правка, новое сообщение или снятие резерва убирают готовность; HTML печати показывает черновик. Повтор подтверждения уже подготовленной неизменённой заявки сохраняет время подготовки.
- Ручное исправление типа симптома обновляет обязательные вопросы; исходный текст и исходный разбор остаются неизменными.
- Некорректные поля API, слишком короткое сообщение, отрицательное количество и попытка прислать `ready=true` отвергаются валидацией. HTML из клиентского сообщения экранируется в печати.
- Повреждённый Excel, отсутствующий лист, формула, исходный резерв выше остатка и конфликт справочника дают отчёт с ошибкой; частичного импорта нет. Демо загружается отдельно и повторно не дублируется.
- LLM проверялась **только с MockTransport**: корректная схема и цитаты, HTTP 503, тайм-аут, отказ, незавершённый ответ, неверный JSON, выдуманная цитата, неизвестное поле. Во всех ошибочных случаях работает локальный откат. Запрос не даёт модели полномочий менять готовность или склад.

## Восемь браузерных сценариев

1. Загрузка настоящего `.xlsx`, отчёт с предупреждением и повтор без дублей.
2. Поиск, фильтры, пустой результат, сброс и отображение точной машины.
3. Новое сообщение → машина → уточнения → цель → F010/Тула → повтор подтверждения резерва → подготовка → предпросмотр → PDF → уточнение → снятие готовности.
4. Нулевой свободный остаток: настоящий отказ резерва виден в интерфейсе.
5. Неизвестная машина: маршрут менеджеру без ложной готовности.
6. Объединение уточнения той же течи с сохранением исходных сообщений.
7. Узкий экран 390 × 844 без выхода документа за ширину.
8. Сетевая ошибка: явное сообщение и успешное восстановление очереди.

Файл `artifacts/workflow-measurement.json` содержит длительность робота от открытия формы до сохранения PDF. В проверенном прогоне — **1 998 мс**. В него не входит реальное ожидание клиента и нет человека: это **не измерение экономии времени диспетчера**.

## Обнаруженные и исправленные проблемы

1. SQLite-соединение могло создаваться и использоваться разными потоками FastAPI, что приводило к `ProgrammingError`. Исправлено создание отдельного соединения на запрос с поддержкой передачи между worker-потоками; конфликт последней детали проверен повторно.
2. Уточнение адреса «на Садовой» не совпадало с формой «Садовая» в реестре. Добавлено ограниченное сравнение основы названия и исключение сегмента «на Ленина всё в порядке».
3. Формы слов «о течи» и фраза о датчике уровня терялись при разборе. Добавлены варианты; дополнительные нераспознанные синонимы не скрыты из оценки, доступна ручная классификация.
4. Ответ «не знаю» мог считаться закрытым вопросом. Для обязательных ответов добавлена проверка неопределённости, для кода — формата E + две цифры.
5. Ручной выбор машины, отличной от единственного кандидата, мог не требовать объяснения. Теперь это отдельная проверка противоречия.
6. Пустая дата визита могла приводить к сравнению `None` со строкой при перевозе. Исправлена обработка пустой даты; готовность остаётся заблокированной.
7. Повторный импорт показывал историческое число созданных сообщений как новые для повторного запроса. Возвращается 0 новых записей, история первого импорта сохраняется.
8. В браузерных тестах обнаружены неустойчивые точные подписи вложенных полей. Ключевым полям добавлены явные `aria-label`; тесты проходят после повторного монтирования форм.
9. Первые предположения теста о количестве результатов поиска и статусе повторного импорта были неверны. Исправлены ожидания: поиск 211 находит два связанных обращения, повтор файла показывает «Уже импортирован».
