# Измерение времени диспетчеров: протокол до начала сбора данных

Версия 1, 12.11.2026. Человеческих наблюдений на момент подготовки протокола **0**. Автотесты и браузерные роботы не заменяют участников. Обновление проекта разрешено пользователем, включая отправку в `sonick6969/ai_hack`.

## Главная метрика и ограничение качества

Основная метрика — активное время от начала работы над обращением до **корректной полной карточки**. Подготовка считается корректной после независимой проверки инженером. Отдельно публикуются календарное время, ожидание клиента/склада/старшего инженера, перерывы, доработка, неучтённые интервалы, незавершённые задачи и ошибочные отметки готовности.

Ускорение = `(медиана ручного процесса − медиана пилота) / медиана ручного процесса`. Это описание эксперимента, не заранее доказанный эффект. Пользовательская цель — уменьшить время без увеличения критичных ошибок; обещание «идеала» или числового выигрыша до наблюдений не даётся.

## Как провести сравнение

1. Владелец исследования описывает текущий ручной процесс (Excel/CRM, шаблон карточки, доступные источники). Его нельзя молча заменить специально неудобной формой.
2. Пригласить действующих диспетчеров. Пробные участники и автоматические проверки регистрируются отдельно и исключаются из основной оценки. Идентификаторы участников — условные коды, например Д-01; проверка их должности остаётся у организатора, поскольку в пилоте нет аутентификации персонала.
3. До запуска зафиксировать сопоставимые пары задач и ключ сравнения. Оба метода получают одинаковые реестр, историю, складской снимок и правила. Один человек не решает буквально одно обращение дважды: это измеряло бы запоминание. Внутри пары использовать разные, сопоставимые по сложности машины/жалобы; соответствие подтверждает инженер.
4. Распределить порядок: часть участников начинает с ручного процесса, часть — с пилота (AB/BA). Перед зачётными задачами дать одинаковую тренировку, пометить её как пробную. Не сравнивать обученного оператора с новичком.
5. Начать таймер перед первой работой. Чтение и работа в Excel/CRM считаются работой; смена вкладки сама по себе не является перерывом. Ожидание и перерыв включаются явно. Пульс браузера подтверждает присутствие, а разрыв более 120 секунд отмечается как неизвестное время, не как «ноль работы».
6. Завершить замер, когда результат сформирован. В ручном режиме приложить текст полученной карточки после остановки таймера: копирование для исследования не должно замедлять контрольный процесс. В пилоте сохраняется снимок карточки и версии заявки.
7. Независимый инженер проверяет обезличенный результат по восьми разделам и критичным ошибкам, по возможности без информации о методе. Самопроверка участника не принимается. Проверка сохраняется для конкретного снимка; дальнейшая правка требует новой проверки.
8. При ошибке продолжить **тот же** замер для доработки. Время исправлений добавляется. Не удалять неудачную попытку и не выбирать самую быструю из повторов. Для парного анализа используется первая зарегистрированная попытка в каждой комбинации участник/пара/метод; повторы показаны отдельно.
9. Начать с 3 диспетчеров и 6 сопоставимых пар на каждого (36 задач), если состав команды это позволяет. Это пилотная оценка, не достаточное основание для вывода о всей отрасли. При меньшем числе участников вывод описательный; отсутствие статистической мощности не скрывать.

## Обязательные выгрузки

- Все зарегистрированные попытки, включая незавершённые и отклонённые, с причинами исключения из основного сравнения.
- Число участников и задач на метод, медиана, квартильный интервал, диапазон и время ожидания.
- Парные результаты по одному участнику и ключу сравнения; сколько пар ещё не готово.
- Числители/знаменатели проверки качества и ложной готовности. Быстрые ошибочные результаты не объявляются улучшением.
- Разделение действующих диспетчеров, пробных участников и автоматизации. CSV не должен превращать текстовые поля в Excel-формулы.

## Важные границы

Сервер считает время по своим отметкам; клиент не передаёт произвольную длительность. Таймер — инструмент наблюдения, а не доказательство, что перед компьютером действительно работал диспетчер. Неизвестные интервалы показываются и исключаются из точного сравнения по заранее объявленному правилу; все такие попытки остаются в отчёте. При работе вне браузера его необходимо оставить открытым. До появления реальных участников отчёт честно показывает отсутствие измерения.

Реальные повторные выезды и финансовый эффект требуют дальнейшего наблюдения. Изменение числа кликов, задержки API и время робота — отдельные технические показатели.
